# 開場與敘事結構

以下 38 種起手式是本地編輯提示，不是上游原文。每種都必須由實際來源支持，不能捏造困境或數字。

1. 先提出使用者正遇到的問題。
2. 展示一個可重現的失敗。
3. 先給結論再說明條件。
4. 比較同一任務的兩種方法。
5. 指出一個常見誤解。
6. 提出可驗證的反例。
7. 展示第一個操作結果。
8. 從一個實際案例開始。
9. 說明當前方法的限制。
10. 呈現一個已確認的數字。
11. 展示前後差異並註明條件。
12. 用一個簡單問題引導觀察。
13. 先指出最重要的選擇。
14. 展示少一個步驟的流程。
15. 說明錯誤會在哪裡出現。
16. 以使用者目的整理資訊。
17. 先預告可交付的成果。
18. 用熟悉的物件解釋概念。
19. 從最小可行範例開始。
20. 提出一個需要取捨的條件。
21. 展示兩種不同輸入的結果。
22. 說明何時不適合使用方法。
23. 以一個觀察推導下一步。
24. 從操作前的準備開始。
25. 用檢查清單呈現必要條件。
26. 展示資料如何進入流程。
27. 呈現結果如何被檢查。
28. 把抽象流程拆成三個動作。
29. 從聽眾熟悉的痛點開始。
30. 展示一個可檢查的假設。
31. 以限制條件引出設計理由。
32. 先問需要哪種輸出。
33. 展示錯誤修正前後的狀態。
34. 說明不同角色各需什麼資訊。
35. 展示一個邊界案例。
36. 從可重複的量測開始。
37. 說明不確定性來自哪裡。
38. 以明確下一步結束開場。

SCQA：先交代情境，再指出衝突，提出問題，最後回答。適用於需要說明決策理由的內容。
PAS：指出問題，說明實際影響，再提出解法。不得誇大風險來製造焦慮。
FAB：功能 → 帶來的能力 → 對使用者的具體利益。每一步都需要可追溯的證據。

先選擇符合目的的結構，再填入事實。不要讓公式取代真實內容。
