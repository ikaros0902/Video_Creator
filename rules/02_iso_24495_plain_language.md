# ISO 24495-1 淺白語言規範（人類閱讀文件專用）

凡給人類團隊、專案擁有者與開源貢獻者閱讀的繁體中文文檔（`README.md`、`00_docs/`、`02_workflows/`、`05_references/`、`06_projects/*/README.md`），一律依循 **ISO 24495-1（Plain Language）** 四大原則，並嚴禁 AI 公文腔與翻譯腔。

## 四大核心原則

| 原則 | 意義 | 在本專案的做法 |
| :--- | :--- | :--- |
| **1. Findable（找得到）** | 讀者能在 10 秒內定位解答 | 一頁聚焦一個任務；標題即問題或動作；重要指令放最上方 |
| **2. Understandable（看得懂）** | 第一次讀就完全明白 | 短句為主（每句 <= 35 字）；先講結論與範例，再講原理；技術名詞附白話解釋 |
| **3. Usable（做得到）** | 看完能立刻複製指令執行 | 指令保留完整可複製路徑（如 `.venv\Scripts\python.exe -m vc doctor`）；標出預期結果 |
| **4. Relevant（只給需要的）** | 刪掉與目標無關的背景吹噓 | 移除空泛形容詞（「強大的」「革命性的」「全方位賦能」），只寫真實數據與步驟 |

## 繁體中文淺白潤色對照表

- **移除被動翻譯腔**：
  - 寫：「先驗證腳本，再輸出配音。」
  - 不寫：「腳本應在進行語音合成操作之前被執行驗證作業。」
- **動詞明確、主語清楚**：
  - 寫：「`vc render` 會先啟用 RTX GPU 算圖；失敗時自動改用 CPU 重試。」
  - 不寫：「系統提供智慧化的異質加速運算體驗。」
- **去 AI 味禁用詞清單**（不得出現在任何教學或說明文檔）：
  - `值得一提的是`、`不僅如此`、`賦能`、`無縫對接`、`顯著提升`、`開創性`、`一站式`、`痛點`。
- **程式碼註解雙軌分流**：
  - Python / TypeScript / PowerShell 檔案註解用繁體中文；
  - `vc/manim_scenes.py` 等幾何腳本保持純英文 ASCII，避免渲染環境字型與編碼衝突。
